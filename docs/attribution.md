# Commit and pull request attribution

When Alran Code makes a commit for you, the message ends with a line that says so:

```text
Co-Authored-By: Alran Code using Werk 1.1 <noreply@alran.dev>
```

The model is the one that ran the turn: `Werk 1.1`, `Sonnet 5.5`, `Opus 5.5`, or, for a model you added
yourself, its id. A pull request description the agent writes ends with

```text
Generated by [Alran Code](https://alran.dev)
```

Both are on by default. `config.yaml` in the data directory switches either off:

```yaml
attribution:
  commits: false        # no trailer, and the reminder stops asking for it
  pullRequests: false   # no "Generated by" line
```

Alran Code reads `config.yaml` when it starts, so restart it after editing the file.

## How it works

Two things carry the commit line, so a model that ignores one still gets signed:

- **A system reminder** tells the model the exact lines to write. It goes into the conversation once per
  session, again after a compaction dropped it, and again when you switch models (the commit line names the
  model). Your own instructions (an `AGENTS.md`, a memory) take precedence over it: if you tell the agent
  to write something else, it does.
- **The `git` the agent runs adds the trailer itself.** The agent's shell has a small `git` shim ahead of
  the real one on its PATH (`<data dir>/shims/git-attribution/git`). It runs the real `git` unchanged, except
  for `git commit` (also through an alias that expands to it), where it adds
  `--trailer "Co-Authored-By: …"`. Git puts the trailer at the end of the message however the message was
  given (`-m`, `-F`, a heredoc, an editor, `--amend`), and the line appears once even when the model wrote
  it too. Only commits made by the agent are touched: the shim is not on your own PATH.

The pull request line has the reminder only: a description reaches `gh` or an API in too many shapes
(`--body`, `--body-file`, an editor, a web form) to add text to it reliably.

## Limits

- **Windows:** the shim is not installed (a PowerShell session has no PATH shim to put in front of `git`).
  The reminder still applies, so the commit line depends on the model following it.
- **A git older than 2.32** has no `git commit --trailer`: the shim then runs git unchanged rather than fail
  the commit.
- **A commit that does not go through PATH** is not signed: `git` called by its absolute path
  (`/usr/bin/git commit`), or a `git commit` inside a git hook (the shim takes its own directory off the PATH
  of the git it runs, so the programs git starts do not find it). A script the agent starts that calls plain
  `git commit` is signed.
- **Other `git` wrappers** (version managers, low-priority dispatchers) keep working: the shim runs the real
  git with its own directory taken off PATH, so a wrapper that looks for "the next git" cannot find the shim
  again.
- A merge, a cherry-pick or a revert makes a commit without `git commit`; their messages are git's own.
